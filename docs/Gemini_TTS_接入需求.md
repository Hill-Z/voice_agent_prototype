# 语音机器人接入 Gemini TTS 需求文档

> 文档状态：评审优化稿  
> 版本：V1.0  
> 更新日期：2026-08-24  
> 适用范围：语音机器人单说话人实时播报

## 1. 背景与目标

语音机器人需要新增 Google Cloud Gemini TTS，以提升客服话术的自然度、情绪表达和多语言覆盖能力。本期最重要的业务目标是验证并上线宿务语和菲律宾语，同时验证菲律宾真实通话中常见的宿务语、菲律宾语与英语混合朗读。

本期目标：

1. 接入 Google Cloud Text-to-Speech API 提供的 Gemini TTS。
2. 固定使用 Gemini 2.5 Flash，并支持选择音色、语言、语音风格和电话音频格式。
3. 首批重点支持宿务语 `ceb-PH`、菲律宾语 `fil-PH` 和英语 `en-US`。
4. 在原始音频和真实电话链路中验证纯语言及混合语言朗读效果。
5. 由海外菲律宾真人进行盲听评测，达到验收门槛后才能开放生产使用。
6. 建立延迟、稳定性、容量、费用和降级机制，满足语音机器人连续对话需要。

原需求中的“高崇合成”疑似笔误，本文按“高质量、可用于电话场景的合成”理解，同时纳入高并发容量验证。

## 2. 评审结论

原需求可以作为产品调研记录，但不能直接进入开发，主要缺少以下内容：

1. **“自动检测语言”表述不准确。** 官方请求示例仍要求填写 `languageCode`。同一音色可以搭配多种受支持语言，不等于 API 承诺自动识别语言。系统必须明确语言来源和混合语言处理策略。
2. **音色 ID 有翻译错误。** 中文网页将 `Charon`、`Enceladus`、`Iapetus` 显示成“冥卫一”“土卫二”“土卫八”。接口必须使用英文 ID，不能提交中文翻译名。
3. **语言清单不完整。** 原稿只列出预览语言，遗漏 24 个 GA（正式发布）语言。当前共列出 87 个语言/地区代码，其中宿务语和菲律宾语仍为预览状态。
4. **未确定 API 路线。** Gemini TTS 同时可通过 Cloud Text-to-Speech API 和 Vertex AI API 调用。语音机器人需要多种电话编码，并需要分块发送文本，因此本期选 Cloud Text-to-Speech API。
5. **未区分模型。** 2.5 Flash、2.5 Flash Lite Preview、2.5 Pro 的定位、上线状态和多说话人能力不同，不能只写“Gemini TTS”。
6. **未覆盖实时限制。** Cloud TTS 的流式接口要等客户端发送 Half-Close 后才开始合成，不能假设 LLM 每生成几个字就能立即出音频。
7. **没有工程边界。** 缺少输入大小、音频时长、格式、区域、权限、配额、超时、重试、降级和费用要求。
8. **“混合朗读效果好”不可验收。** 缺少语料、试听人员、评分维度、样本量和通过标准。
9. **没有电话链路测试。** 24 kHz 原始音频好听，不代表经过 8 kHz 电话链路后仍可用。
10. **没有预览功能风险控制。** `ceb-PH` 和 `fil-PH` 均为 Preview，质量或可用性可能变化，必须支持灰度、关闭和回退。
11. **未说明新版模型范围。** 官方英文页面当前还列出 `gemini-3.1-flash-tts-preview`。该模型整体仍为 Preview，本期只保留实验跟踪，不纳入生产接入和验收范围。

## 3. 范围

### 3.1 本期范围

- 单说话人实时语音合成。
- 仅使用 Gemini 2.5 Flash TTS。
- 宿务语、菲律宾语、英语及三者混合文本。
- 音色试听、机器人选用、语言设置和自然语言风格提示。
- 同步合成及面向语音机器人的流式音频返回。
- 电话链路音频编码和实际呼叫验证。
- 运行监控、成本统计、失败重试和降级。

### 3.2 本期不做

- 多说话人播客或角色对话。
- Gemini 2.5 Pro TTS 和 Gemini 2.5 Flash Lite Preview。
- Gemini 3.1 Flash TTS Preview 的生产开放。
- 自定义音色、声音克隆和音色训练。
- 长篇有声书生成。
- 将 SSML 作为 Gemini TTS 的正式能力；如需停顿、重音或读法控制，本期优先使用自然语言提示并实测。

## 4. 关键产品决定

### 4.1 API 选择

本期使用 **Google Cloud Text-to-Speech API**，原因如下：

- 可直接指定 `LINEAR16`、`ALAW`、`MULAW`、`MP3`、`OGG_OPUS`、`PCM` 等格式。
- 支持客户端发送多个文本块并接收多个音频块。
- 更适合现有语音机器人和电话音频链路。

Vertex AI API 本期不接入。其输出固定为无 WAV 文件头的 16 位 24 kHz PCM，且文本流式方式为单次请求、多次响应。

### 4.2 模型策略

本期唯一模型为 `gemini-2.5-flash-tts`。模型 ID 由平台级配置统一管理，机器人配置页不提供模型切换。平台仍需保留紧急关闭能力，但不开放 Pro、Flash Lite 或 3.1 Preview。

### 4.3 语言策略

1. 每次请求必须显式提交 BCP-47 `languageCode`。
2. 机器人必须配置“主要朗读语言”，菲律宾场景可选 `ceb-PH`、`fil-PH` 或 `en-US`。
3. 开启“自动语种跟随”时，语言代码来自上游已确认的当前回复语言，不依赖 TTS 自行检测。
4. 上游没有可靠语言结果时，使用机器人主要朗读语言。
5. 单句混合文本使用该句主语言作为 `languageCode`；不得把一句话拆成多个音色后再拼接，以免音色和节奏跳变。
6. 对混合文本的支持按实际效果验收，不对外承诺所有语言组合都能自动、稳定切换。

## 5. 功能需求

### 5.1 平台配置

管理员可配置：

- Google Cloud 项目 ID。
- 区域：默认 `global`，可按合规要求选择已支持区域。
- API 地址：根据区域自动生成，不允许用户手填任意地址。
- 凭证引用：仅保存安全凭证标识，不展示或回传密钥内容。
- 模型 ID、请求超时、重试次数、并发上限和降级策略。
- 平台级启用、灰度和紧急关闭开关。

凭证只能存放在服务端，禁止写入前端、日志、数据库明文字段或需求示例。项目必须启用 Cloud Text-to-Speech、结算，并为运行身份授予调用模型所需的 `aiplatform.endpoints.predict` 权限。

### 5.2 机器人配置

机器人 TTS 配置新增 Google Gemini：

- 厂商：Google。
- 音色：显示名称、英文 ID、性别、试听按钮和可用状态。
- 主要朗读语言。
- 自动语种跟随开关。
- 风格提示：可填写语气、口音、语速、语调、情绪等自然语言要求。
- 输出格式：由电话线路配置自动决定，普通用户不直接修改。
- 降级音色：Gemini 不可用时切换到已配置的备用 TTS。

保存时必须校验音色和语言非空，调用前由平台补充固定模型 ID。预览语言旁显示“预览能力，质量和可用性可能变化”。

### 5.3 音色试听

1. 音色列表使用附录 A 中的英文 ID。
2. 每个音色至少提供宿务语、菲律宾语、英语和混合语言四段统一试听文本。
3. 试听必须展示所用模型、语言代码、风格提示和音频格式，保证结果可复现。
4. 同一轮盲听不得向试听者展示音色名称、模型或厂商，避免品牌偏见。
5. 最终生产音色从真人盲听结果中选择，不仅依据产品人员主观试听。

### 5.4 文本处理与合成

请求至少包含：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `modelName` | 模型 ID | 必填，来自配置 |
| `name` | 音色 ID | 必填，使用英文 ID |
| `languageCode` | 语言代码 | 必填，使用 BCP-47 |
| `text` | 待读文本 | 必填，UTF-8；单次不超过 4,000 字节 |
| `prompt` | 朗读风格提示 | 可选；单次不超过 4,000 字节 |
| `audioEncoding` | 音频编码 | 根据线路和播放端选择 |
| `sampleRateHertz` | 采样率 | 根据线路能力配置并验证 |

文本和提示合计不得超过 8,000 字节。预计音频超过约 655 秒时必须在调用前拆分，不得依赖服务端截断。

文本预处理要求：

- 保留宿务语、菲律宾语和英语原文，不做自动翻译。
- 清除内部标签、Markdown、控制指令和不可朗读字符。
- 对订单号、电话号码、金额、日期、时间、网址、缩写和人名提供可配置的读法替换。
- 不得修改原始业务文本；朗读文本与原始文本分别记录。
- 风格提示和业务文本必须使用独立字段，禁止把不可信业务文本拼入系统级控制提示。

混合语言处理要求：

1. 一个请求只允许提交一个 `languageCode`；它是字符串，不是数组。
2. 同一句中混合宿务语、菲律宾语和英语时，原文整体提交，`languageCode` 选择该句占主导的语言。
3. `prompt` 明确要求保留其他语言片段的原始读法，不翻译、不统一成主语言。
4. 如果一句内的混读效果未通过真人试听，再按完整句子或明确语言边界拆成多个请求；所有请求保持同一音色。
5. 不允许在单词、姓名、数字或缩写中间拆分。拆分后应控制句间停顿和音量一致，并计入实际 QPM。

同步请求示例：

```json
{
  "input": {
    "prompt": "Use a natural Filipino customer-service voice. Preserve Cebuano and English phrases in their original language. Do not translate or omit any content.",
    "text": "Maayong adlaw! Kumusta po? Your order is ready na for pickup."
  },
  "voice": {
    "languageCode": "fil-PH",
    "name": "Kore",
    "modelName": "gemini-2.5-flash-tts"
  },
  "audioConfig": {
    "audioEncoding": "MULAW",
    "sampleRateHertz": 8000
  }
}
```

请求地址为 `POST https://texttospeech.googleapis.com/v1/text:synthesize`。如果整句以宿务语为主，将 `languageCode` 改为 `ceb-PH`；如果以英语为主，则改为 `en-US`。具体主语言不能只按字符数判断，应由生成回复的上游模型同时输出，无法判断时使用机器人主要朗读语言。

### 5.5 实时播放与分段

1. 合成服务按完整短句或可独立朗读的语义块提交，推荐每块 15 至 80 个字符，不能在数字、人名、缩写或单词中间截断。
2. Cloud TTS 流式连接只有在客户端 Half-Close 后才开始合成。因此，首包延迟从“当前语义块提交完毕”开始计算，不能从 LLM 首字输出开始计算。
3. 接收到音频块后立即向播放链路转发，不等待完整音频生成完成。
4. 句间拼接必须避免爆音、重叠、异常停顿和音量跳变。
5. 用户打断时立即停止向播放端发送剩余音频，并取消未开始的后续合成；无法取消的响应应丢弃，不得继续播放。
6. 同一通话内模型、音色、主要语言和核心风格保持一致，除非业务明确切换语言。

### 5.6 音频格式

- 普通试听优先保留 24 kHz 原始音频，用于评价模型真实质量。
- 电话场景按现有线路使用 `MULAW` 或 `ALAW`，并验证 8 kHz 播放效果。
- 如果 API 返回格式与线路格式不同，只允许在统一音频服务中转码。
- 上线验收必须同时通过原始音频和真实电话呼叫，不能只听电脑扬声器样本。

### 5.7 缓存

固定欢迎语、结束语和高频静态话术允许缓存。缓存键必须包含模型、音色、语言、风格提示、文本、编码和采样率。动态变量话术默认不缓存，避免播放他人的姓名、订单或账户信息。

## 6. 异常处理与降级

| 场景 | 处理方式 |
| --- | --- |
| 认证或权限失败 | 不重试；告警并切换备用 TTS |
| 参数错误、文本超限 | 不重试；记录明确原因并使用安全兜底话术 |
| 429 限流 | 短暂指数退避；超过本轮时限后切换备用 TTS |
| 5xx 或网络失败 | 最多重试 1 次；仍失败则切换备用 TTS |
| 首音频超时 | 取消本次请求，播放预录连接词或切换备用 TTS |
| 返回空音频、损坏音频 | 视为失败，不允许静默播放 |
| 预览语言质量异常 | 可按语言单独关闭 Gemini，回退到指定厂商或录音 |

同一句话因播放失败重试时必须避免重复播报。日志中要有全链路请求 ID，但不得记录凭证和完整敏感文本。

## 7. 非功能需求

### 7.1 延迟

在菲律宾目标部署区域、生产同等网络和电话链路下统计：

- 当前语义块 Half-Close 到首个可播放音频块：P50 不高于 800 ms，P95 不高于 1,500 ms。
- 端到端机器人回复延迟需单独统计 ASR、LLM、分段等待、TTS 首包和电话播放缓冲。
- 指标未达标时不得以缩短到破坏语义的文本块方式规避。

以上为产品目标，必须以 POC 实测数据确认；如果官方服务在目标网络下无法达到，应在评审会上重新决定是否上线，不能静默放宽。

### 7.2 稳定性

- 合成请求成功率不低于 99.5%，不含明确的无效参数请求。
- 成功响应但无可播放音频的比例低于 0.1%。
- 连续 30 分钟压力测试期间无音频串话、错播、顺序错误或资源持续增长。
- 服务故障时，备用 TTS 切换成功率不低于 99.9%。

### 7.3 容量与配额

官方当前默认上限：

- `gemini-2.5-flash-tts`：150 QPM。
- Cloud TTS 项目级并发流式会话默认上限：100。

上线前必须用“峰值同时通话数 × 每通电话每分钟平均回复次数”计算所需 QPM，并预留至少 30% 余量。拆成多个短句会增加请求数，容量计算必须按实际请求数，而不是按通话数。若默认配额不足，必须在上线前完成配额申请或限制灰度流量，不得通过轮换项目规避配额。

### 7.4 成本

当前公开价格没有免费额度：

- Gemini 2.5 Flash：文本输入每百万 token 0.50 美元，音频输出每百万 token 10 美元。
- 音频按每秒 25 个 audio token 计算。

平台必须记录模型、输入 token、输出音频时长、估算费用、机器人和租户。月度预算达到 80% 时预警，达到 100% 时按平台策略限流或降级。价格会变化，系统价格表必须可配置，不能硬编码在业务逻辑中。

### 7.5 安全与合规

- 使用服务账号或工作负载身份，遵循最小权限原则。
- 生产和测试使用不同项目或身份。
- 明确所选区域的数据驻留范围，并完成公司内部合规评审。
- 供应商请求日志、平台日志和试听样本不得包含不必要的个人敏感信息。
- 真人试听语料使用脱敏或虚构数据，试听人员需知晓音频仅用于产品评测。

## 8. 菲律宾语言质量测试方案

### 8.1 测试人员

至少邀请 6 名当前居住在海外的菲律宾真人参加盲听：

- 至少 3 名以宿务语为第一语言。
- 至少 3 名以菲律宾语为第一语言。
- 所有人都能理解菲律宾常见英语混用表达。
- 优先覆盖 Cebu、Davao 或其他主要宿务语使用地区，记录其语言背景，但报告中匿名。
- 试听者不能是本项目开发者，也不能提前知道音色或模型名称。

### 8.2 候选范围

先由产品团队从 30 个音色中筛选 3 个女声和 3 个男声，再进行正式盲听。所有候选都使用 Gemini 2.5 Flash、同一组文本和同一套提示。正式评测组合不得在中途更改提示词。

### 8.3 测试语料

每类至少 20 条，总计不少于 140 条：

1. 纯宿务语客服句。
2. 纯菲律宾语客服句。
3. 纯菲律宾英语客服句。
4. 宿务语为主、夹菲律宾语和英语。
5. 菲律宾语为主、夹宿务语和英语。
6. 人名、地名、品牌、缩写、网址、邮箱。
7. 电话号码、订单号、金额、折扣、日期和时间。

语料需包含疑问、确认、道歉、提醒、催促、安抚和结束通话等客服语气。每条保留“期望读法”，数字和专有名词由菲律宾业务人员确认。

### 8.4 试听条件

每条样本制作两个版本：

- 24 kHz 原始版本。
- 经过生产电话线路实际呼叫或等效 8 kHz 编码后的版本。

试听顺序随机，响度统一，不展示文本以外的模型信息。至少 20% 样本重复出现，用于检查同一试听者评分是否稳定。

### 8.5 评分维度

每项使用 1 至 5 分：

- 发音准确度。
- 可懂度。
- 自然度。
- 宿务语/菲律宾语/英语切换自然度。
- 语气是否符合客服场景。
- 语速、停顿和重音。
- 同一音色跨语言的一致性。

另外逐条标记严重错误：数字读错、否定词读错、金额读错、姓名不可辨认、语言切换失败、漏读、重复或产生文本中不存在的内容。

### 8.6 上线门槛

候选音色必须同时满足：

- 原始音频综合平均分不低于 4.0。
- 电话音频综合平均分不低于 3.8。
- 发音准确度和混合语言切换两项均不低于 3.8。
- 至少 80% 的试听者认为“可用于真实客服通话”。
- 数字、金额、日期、电话和订单号的准确读出率不低于 99%。
- 否定、金额、日期等可能改变业务含义的严重错误为 0。
- 宿务语第一语言组和菲律宾语第一语言组必须分别达标，不能只看合并平均分。

任一核心场景不达标，不能用其他场景的高分抵消。未通过的模型、音色或语言组合不得出现在生产配置中。

## 9. 技术验收用例

### 9.1 正常功能

- 可使用 Gemini 2.5 Flash 合成并播放音频。
- 30 个音色 ID 均能正确提交，列表不会发送中文翻译名。
- `ceb-PH`、`fil-PH`、`en-US` 可分别合成。
- 自动语种跟随使用上游语言结果，缺失时正确回退主要语言。
- 宿务语、菲律宾语和英语混合句保持同一音色，且不漏读。
- 风格提示能改变语气，但不会改变事实内容。
- 电话链路可正确播放 `MULAW` 或 `ALAW` 音频。
- 用户打断后剩余音频不再播放。

### 9.2 边界与异常

- 中英文及菲律宾语言多字节文本按 UTF-8 字节数拦截，不按字符数误判。
- 文本、提示和合计大小达到限制时有明确提示。
- 超过预计 655 秒的文本能预先拆分。
- 429、5xx、超时、空音频、损坏音频均能告警和降级。
- 凭证错误不重复重试，不在界面或日志中暴露凭证。
- 并发合成时音频不会串到其他通话。
- 同一通话连续多句的音量、音色和风格保持稳定。

### 9.3 上线检查

- 官方语言状态、价格、配额、区域和模型状态已在上线当日复核。
- 生产项目已启用 API、结算、权限和监控。
- 峰值 QPM 计算和配额申请已完成。
- 菲律宾真人盲听报告已签字确认。
- 真实电话链路、压力测试和故障降级全部通过。
- 平台级紧急关闭和语言级回退已演练。

## 10. 监控与日志

每次请求记录：

- 请求 ID、通话 ID、机器人、租户。
- 模型、音色、语言代码、区域、音频格式、采样率。
- 文本和提示字节数；敏感文本仅记录脱敏摘要或哈希。
- 请求开始、Half-Close、首音频、结束时间。
- 首包延迟、总耗时、音频时长、重试次数和结果码。
- 是否命中缓存、是否发生降级及降级原因。
- 估算 token 和费用。

监控面板至少包含成功率、P50/P95 首包延迟、429、5xx、空音频、降级率、QPM、并发会话、分语言质量投诉和费用趋势。

## 11. 灰度与发布

1. 开发环境完成 API 和音频格式验证。
2. 测试环境完成全量语料合成和内部筛选。
3. 完成海外菲律宾真人盲听，确定允许上线的模型、音色、语言和提示。
4. 仅向内部测试机器人开放。
5. 按 5%、20%、50%、100% 流量灰度，每阶段至少观察一个完整业务高峰。
6. 任一阶段出现严重读错、成功率低于目标、P95 延迟超标或配额不足，立即回退。
