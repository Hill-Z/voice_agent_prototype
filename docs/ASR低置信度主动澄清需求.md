# ASR 识别不清主动澄清需求

## 一、目标

当 ASR 对用户本轮语音的最终识别结果缺乏把握时，不允许大模型直接回答或执行工具；系统结合置信度、候选文本和已确认的历史上下文，选择有针对性的确认或请用户重复，降低答非所问和错误执行的风险。

## 二、前端配置

在机器人「ASR 识别配置」中增加一个开关：

**识别不清时主动澄清**

悬停说明：

> 开启后，系统在语音识别结果不够可靠时，将请客户重新表达，不使用本次识别内容进行回答。

客户只能开启或关闭，不展示和调整置信度阈值。阈值由平台按 ASR 厂商、模型和语言统一管理。

## 三、处理逻辑

仅处理 ASR 返回的最终识别结果，流式中间结果不参与判断。

平台内部使用两个阈值，客户仍只看到一个开关。初始值仅用于灰度，后续按厂商、模型和语言校准：

```text
最终识别结果
├─ 可靠区（建议初始值 ≥ 0.80）→ 正常写入上下文并调用 LLM
├─ 不确定区（建议初始值 0.55～0.80）→ 受限 LLM 结合历史上下文生成澄清问题
├─ 不可用区（建议初始值 < 0.55）→ 不调用 LLM，直接播放固定重述话术
├─ 置信度缺失或当前模型不可靠 → 不执行置信度拦截，按正常链路处理并记录
├─ 没有识别到语音 → 进入现有“未检测到输入”处理
└─ ASR 调用失败 → 进入现有 ASR 异常处理
```

不确定或不可用区的识别文字不得作为已确认用户事实写入：

- 大模型对话上下文；
- 工具调用和流程判断；
- 信息提取和业务分析。

后台可保留脱敏后的原始识别结果、分数和拦截原因用于排查。客户通话记录中标记为“识别不清，已请求重述”，不把模糊文字当作有效对话展示。

但不确定区的识别文字、最多 3 条 ASR 候选及其分数，可以作为一次性的 `uncertain_input` 交给受限 LLM。它只用于生成澄清问题，不写入长期对话历史，也不能触发工具。

受限 LLM 仍能读取此前已经确认的完整对话历史，因此不会丢失上下文。系统生成并播放的澄清问题可以作为机器人回复写入历史；下一轮客户给出可靠回答后恢复正常流程。

## 四、澄清策略

### 不确定区：有上下文地确认

受限 LLM 只能输出一句简短澄清问题，禁止回答业务问题、补全事实或调用工具。

示例：上一轮机器人询问“您要查询订单还是申请退款？”，ASR 候选接近“查询订单”时，可以问：

> 您是想查询订单，对吗？

如果候选差异较大或上下文无法缩小范围，则退回通用话术：

> 抱歉，我刚才没有听清，请您再说一遍。

### 不可用区：直接请用户重述

分数过低时，不把模糊文本交给 LLM，直接使用通用话术。话术使用机器人当前配置语言。

### 受限 LLM 提示词

```text
当前用户语音识别结果不确定。你只能生成一句简短的澄清问题，不能回答业务问题、不能调用工具、不能把候选内容当作事实。

请结合已确认的历史对话和 ASR 候选：
1. 如果候选表达的业务含义基本一致，使用“您是想……对吗？”进行确认；
2. 如果候选含义不同或无法判断，请用户重新表达；
3. 不要提及 ASR、置信度、系统错误或技术原因；
4. 不得新增候选中没有出现的姓名、号码、金额、时间或其他事实；
5. 只输出一句话，使用当前机器人的语言，中文建议不超过 30 个字。
```

调用受限 LLM 时必须关闭全部工具，并对输出做长度和单句校验。模型超时、报错或输出不合规时，直接使用通用话术。

### 连续识别不清

同一对话连续出现识别不清时：

1. 第 1 次：优先根据上下文进行针对性确认；无法判断时请用户重复。
2. 第 2 次：不再猜测候选，提示客户放慢语速重新表达，例如“抱歉，还是没有听清，请您放慢一些再说一遍。”
3. 第 3 次：停止继续反问，进入机器人已有全局异常处理；有人工能力则转人工，无人工能力则使用客户已配置的兜底话术结束或返回上一步。

一次可靠识别成功后，连续次数清零。不同业务步骤不共享次数，避免早期的一次失败影响后续正常对话。

## 五、阈值设计

第一阶段可靠区阈值建议从 `0.80` 开始、不可用区阈值从 `0.55` 开始灰度验证，但不能把所有厂商的分数视为同一准确率。置信度只是识别引擎对结果的估计，不等于真实正确率。

后台阈值至少按以下维度分别保存：

```text
ASR 厂商 + 模型版本 + 语言
```

优先使用厂商返回的最终句级置信度。只有词级置信度时，平台适配层统一计算句级分数；建议采用按词时长加权平均，并同时记录低分词占比，避免少数错误关键词被平均值掩盖。

所有厂商输出统一为：

```text
confidenceAvailable：是否有可信分数
confidenceScore：归一化后的 0～1 分数
confidenceSource：句级 / 词级聚合 / 不可用
isFinal：是否最终结果
```

分数缺失、超出 0～1、解析失败，或者某 SDK 长期固定返回 0 时，必须标记为“不可用”，不能直接触发澄清。

## 六、阈值验证

不能只凭主观确定 80%。上线前按主要“厂商 + 模型 + 语言”准备脱敏录音样本，记录人工核对结果，并比较不同阈值下：

- 错误识别被成功拦截的比例；
- 正确识别被错误拦截的比例；
- 主动澄清触发率；
- 客户重复后识别成功率；
- 客户放弃率、转人工率和任务完成率；
- 增加的响应耗时。

先以双阈值灰度测试，再根据真实数据分别调整各模型和语言的可靠区与不可用区边界。阈值调整由平台后台完成，不影响客户配置。

## 七、异常与边界

- 用户静音、背景噪声但没有有效文字：走无输入逻辑，不算低置信度澄清。
- ASR 返回流式中间结果：不得提前反问，等待最终结果。
- 用户只说“嗯、好、对”等短句：仍使用厂商最终分数，单独统计误拦截情况。
- ASR 提供多条候选时：同时参考候选之间的分差；候选分数接近代表歧义更大，应优先确认而不是选择第一条直接执行。
- DTMF 按键输入：不经过 ASR 置信度判断。
- 澄清话术播放期间允许客户打断，并开始新一轮识别。
- 同一轮最终结果只判断一次，防止 ASR 重复回调导致重复播报。
- 机器人切换 ASR 模型或语言时，重新读取对应平台阈值。
- 置信度适配模块异常时应放行原结果并记录告警，不能阻断整通电话。
- 涉及手机号、证件号、金额等关键字段时，即使置信度达到阈值，仍可由业务流程进行复述确认；这与本功能分开处理。

## 八、监控与上线

后台记录机器人、ASR 厂商、模型、语言、分数是否可用、实际分数、是否触发澄清、连续次数和后续结果。识别文字按现有隐私规则脱敏。

先按测试租户和少量机器人灰度开放。平台保留全局关闭能力；发现澄清率或客户放弃率异常升高时，可立即关闭，不修改客户已保存的开关。

## 九、厂商能力调查（2026-09-08）

本表只判断“文字识别结果的置信度”，不把语言识别概率、情绪置信度等其他分数算入。

| ASR 厂商/模型 | 公开能力结论 | 返回形式与限制 | 接入建议 |
| --- | --- | --- | --- |
| 阿里 Paraformer | 暂未提供 | 公开实时接口返回文本、时间戳等；`emo_confidence` 是情绪置信度，不是文字识别置信度 | 暂不启用，向阿里确认私有接口或后续版本 |
| 阿里 Qwen3-ASR | 暂未提供 | 公共 API 和开源推理结果主要返回文本、语言、时间戳，未见文字置信度 | 暂不启用 |
| 腾讯 ASR | 部分产品支持 | 腾讯同传明确支持置信度；标准云 ASR 是否返回取决于当前接入的产品、接口和模型 | 检查现网响应字段，确认后按接口开放 |
| 微软 Azure Speech | 支持 | Detailed 最终结果可返回 0～1 的候选结果置信度；实时中间结果不提供 | 可接入，只使用最终结果 |
| AWS Transcribe | 支持 | 最终分段可返回词级 0～1 置信度，字段可能为空；中间结果会变化 | 可接入，后端聚合为句级分数 |
| ElevenLabs | 部分支持 | 已提供词级 `logprob`，不是直接的百分比；语言概率不能代替文字置信度 | 先确认实时接口，再换算并校准阈值 |
| Fano ASR | 支持迹象明确 | 公开接口模型包含 Token Confidence 等结构，具体字段取决于部署版本 | 联调实际响应后接入 |
| 弧光 ASR | 无法确认 | 未检索到可核验的公开接口文档 | 由厂商提供接口文档或真实响应样例后判断 |

产品结论：第一版可直接支持微软和 AWS；腾讯、ElevenLabs、Fano 需按现网接口联调后开放；Paraformer、Qwen3-ASR、弧光 ASR 暂不能承诺支持。各厂商分数尺度不同，后台必须按“厂商 + 模型 + 语言”分别设置阈值，不能直接共用 80%。
