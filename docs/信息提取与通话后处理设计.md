# 信息提取与通话后处理设计

> 文档状态：原型已实现  
> 更新日期：2026-08-26  
> 当前阶段：已完成仅提取、接口、工具三种方案类型原型

## 1. 背景

信息提取用于在通话结束后，基于完整对话内容，通过大模型提取结构化字段。

当前核心能力包括：

1. 配置需要提取的字段。
2. 选择字段是否展示在通话记录中。
3. 选择接口，将提取结果传输到外部系统。

当前已将接口传输扩展为通用工具调用，同时允许模型根据通话内容判断需要调用的工具。

## 2. 设计结论

信息提取和工具调用必须分开处理，不能让工具调用替代原有的信息提取能力。

完整流程：

```text
完整对话 → 提取结构化字段 → 保存提取结果 → 判断是否执行工具 → 记录执行结果
```

- 信息提取负责回答“这通电话中获得了哪些信息”。
- 通话后处理负责回答“获得这些信息后，需要执行什么动作”。
- 不需要后续动作的客户，只配置字段提取即可。

## 3. 页面结构

页面名称继续使用“信息提取”，分为“提取字段”和“通话后处理”两个区域。

### 3.1 提取字段

模型默认使用以下内容进行分析：

- 完整对话内容
- 通话基础信息
- 通话过程中生成的变量
- 通话中已有的工具返回结果

每个提取字段包含：

| 配置项 | 说明 |
| --- | --- |
| 字段名称 | 客户看到的字段名称 |
| 字段编码 | 系统内部使用的唯一编码 |
| 字段类型 | 文本、数字、布尔值、日期时间、枚举 |
| 提取说明 | 告诉模型如何从对话中判断和提取 |
| 是否必填 | 未提取到必填字段时标记分析不完整 |
| 展示在通话记录 | 开启后在通话记录详情中展示 |

提取结果应保存到对应通话记录，支持后续查询、导出、接口传输和重新分析。

### 3.2 通话后处理

通话后处理为可选能力，默认不执行工具。

处理方式包含：

| 方案类型 | 执行规则 |
| --- | --- |
| 无（仅提取字段） | 只保存大模型提取结果，不调用接口或工具；新配置默认选项 |
| 接口类型 | 继续选择原接口配置方案，并兼容线上已有接口和参数配置 |
| 工具类型 | 从全局工具配置目录中多选候选工具，由模型判断实际调用哪一个或多个 |

选择接口或工具后，配置以下内容：

| 配置项 | 说明 |
| --- | --- |
| 接口或工具 | 接口选择原配置方案；工具使用多选下拉选择候选工具 |
| 提示词 | 接口配置提取要求；工具配置模型调用判断要求 |
| 参数配置 | 支持大模型抽取自定义参数，或把已有业务变量映射到调用参数 |

模型只能从客户预先选择的工具中判断和调用，不能临时选择其他工具。

## 4. 可用于通话后处理的工具

适合通话结束后执行的工具包括：

- 信息传输接口
- 接口工作流
- 创建或更新工单
- 更新客户资料
- 发送短信
- 创建回呼计划

以下工具不应出现在通话后处理的候选列表中：

- 转人工
- 挂断通话
- 通话中播报
- 仅用于实时查询并向客户回复的工具

工具需要标记是否支持“通话后执行”，页面只展示可用工具。

## 5. 模型判断方式

选择“模型判断”时，模型需要根据完整对话和提取结果输出：

- 是否执行工具
- 需要执行的工具
- 工具参数

模型可以明确返回“不执行”。系统负责校验：

- 工具是否在客户授权范围内
- 必填参数是否完整
- 参数类型和格式是否正确
- 是否出现重复执行

模型负责判断业务意图，系统负责控制实际执行。

## 6. 兼容现有配置

已有客户配置不能失效。

- 原有提取字段继续保留。
- 原有“展示在通话记录”配置保持不变。
- 原有“选择接口传输”继续按接口类型读取，不要求客户迁移。
- 原接口继续引用原鉴权配置和参数映射。
- 老配置无需重新保存即可继续执行。

## 7. 执行记录

每次通话后分析需要记录：

- 分析状态和完成时间
- 提取字段及结果
- 使用的配置版本
- 是否决定调用工具
- 实际调用的工具
- 工具入参、执行状态和结果摘要
- 未执行、校验失败或调用失败的原因

这些信息用于通话记录查看、问题排查和重新执行，不需要全部展示在机器人配置页面。

## 8. 当前原型需要调整的方向

当前原型已经完成方案类型、工具多选和参数来源调整，后续重点转向真实执行和通话记录展示。

后续原型调整应当：

1. 方案类型提供无、接口、工具三种选择。
2. 工具从左侧工具配置的共享目录中多选，由模型判断实际调用项。
3. 参数支持大模型抽取和业务变量映射，多工具参数必须指定目标工具。
4. 保持旧信息提取方案和原接口配置兼容。
